# Source Code and Asset Reuse Conditions

*Research snapshot: 2026-10-03. Repository sources are linked at pinned commits where available. This report records published terms and technical requirements; it is not legal advice or blanket clearance for a faithful RCT2 reproduction.*

## OpenRCT2 code

OpenRCT2 describes itself as an open-source re-implementation of RollerCoaster Tycoon 2. Its repository states that the code is licensed under GNU GPL version 3 or any later version. The license text includes conditions for distributing modified source and compiled forms, including providing corresponding source through an allowed GPL route. Porting or adapting OpenRCT2 code into a browser client therefore creates a GPL compliance question for the code that is shipped; the exact scope depends on what is copied and how it is combined. The OpenRCT2 code license does not state that RCT2 graphics, sounds, models, scenarios, names, or other game data are licensed with that code. ([OpenRCT2 README](https://github.com/OpenRCT2/OpenRCT2/blob/11513222890717e81431c83a28aafb7555f2ccd2/readme.md), [pinned license text](https://github.com/OpenRCT2/OpenRCT2/blob/11513222890717e81431c83a28aafb7555f2ccd2/licence.txt))

**Inference and boundary:** Reading OpenRCT2 to understand behavior, while writing new code without copying its implementation, avoids reusing its GPL-licensed source in the ordinary code-reuse sense. That observation does not decide whether reproducing particular game mechanics, interface details, names, branding, scenarios, or visual expression raises other rights questions. The reviewed OpenRCT2 materials do not grant a license to those RCT2 materials or resolve those questions.

## Object definitions, images, and sound

The official OpenRCT2 objects repository says it contains objects from RCT1, RCT2, and their expansion packs. Its repository license file is CC BY 4.0. The repository structure separates JSON object definitions from image files; for example, object folders contain `object.json` and `images/*.png` files. Thus the repository is not merely a catalog of abstract object identifiers. ([objects README](https://github.com/OpenRCT2/objects/blob/978f596972c1163dc670d853dd6add4766f10dbd/README.md), [objects license](https://github.com/OpenRCT2/objects/blob/978f596972c1163dc670d853dd6add4766f10dbd/LICENCE), [example object folder](https://github.com/OpenRCT2/objects/tree/978f596972c1163dc670d853dd6add4766f10dbd/objects/official/footpath_item/rct2dlc.footpath_item.litterpa))

For material actually covered by CC BY 4.0, sharing it requires the specified attribution information, an indication of modifications, and a reference to the license. However, the same license text says that licensors should secure the rights needed to license material, that the license grants only rights the licensor has authority to grant, and that other rights may still restrict use. Because the repository says it contains objects from commercial RCT games, its repository-level CC BY label does not by itself establish that every game-derived image, sound, string, or model is cleared for reuse. I did not find a per-file provenance or rights-exception map in the repository material reviewed. ([CC BY terms included in objects repository](https://github.com/OpenRCT2/objects/blob/978f596972c1163dc670d853dd6add4766f10dbd/LICENCE))

For a separate audio example, OpenSoundEffects states that its code is MIT-licensed while sound effects and associated metadata are CC BY 4.0 unless otherwise specified. Its pinned index still has many original sound slots without a completion check, so it is not a complete replacement sound pack at that snapshot. Check any individual file and its provenance before use; do not treat the audio repository’s general statement as a rights audit of every recording. ([OpenSoundEffects README at pinned commit](https://github.com/OpenRCT2/OpenSoundEffects/blob/877f5d00390c41b599f299ee380992037c1d3f41/README.md))

## Independent 3D assets and replacement-project status

OpenGraphics is an existing effort to make freely usable replacement graphics for OpenRCT2. It states that the project is GPLv3-licensed, asks contributors to use public-domain textures, avoid premade models and copied real-life products, and keep objects the same size and features as RCT2 variants. Its README snapshot identifies small non-vegetation scenery, large scenery, walls, and stalls as current focus areas. It also lists unresolved blockers for peep/ride sprites, track sprites, flat rides, vegetation, and graphics asset packs; the asset-pack implementation had not been merged. This makes it a relevant reference for an independently authored 3D workflow, but not a complete drop-in art set. Using its contributions would also bring their stated GPLv3 license into the project’s asset-license decision. ([OpenGraphics README](https://github.com/OpenRCT2/OpenGraphics/blob/930b0140685f85db92147af832080e8df12d8d4e/README.md), [OpenGraphics license](https://github.com/OpenRCT2/OpenGraphics/blob/930b0140685f85db92147af832080e8df12d8d4e/license.txt))

## Original game data and user-supplied files

OpenRCT2’s installation documentation says it needs object files from RCT2 or RCT Classic, containing graphics, sounds, and models. Its Windows instructions tell the player to install the original game and let OpenRCT2 locate or select the local game-data directory. These are technical requirements for OpenRCT2; the docs do not describe a browser upload workflow or grant permission to repackage, transform, host, or serve the files. ([Getting RCT2](https://github.com/OpenRCT2/docs/blob/86cf40e575605df295c57e97049c67a5108e982c/installing/getting-rct2.rst), [Windows installation](https://github.com/OpenRCT2/docs/blob/86cf40e575605df295c57e97049c67a5108e982c/installing/installing-on-windows.rst))

Atari’s currently published general EULA describes a personal, non-commercial, non-transferable license and prohibits specified distribution, adaptation, reproduction, and derivative-work uses. The page does not identify a particular RCT2 edition, and I did not verify that it is the agreement incorporated into a user’s GOG, Steam, or CD copy. The applicable copy-specific terms therefore remain unresolved. **Inference:** requiring a player to provide their own game files may change who supplies the copy, but it does not by itself establish permission for the project to receive, convert, persist, distribute, or publicly serve those files. A browser feature that uploads files to a server is a separate handling path from OpenRCT2’s documented local-directory setup. ([Atari EULA](https://atari.com/pages/end-user-license-agreement))

## Conditions to carry into project decisions

- A reference-only implementation should keep its code independently authored and treat fidelity questions about RCT2 names, artwork, audio, scenarios, branding, and save compatibility as separate unresolved matters.
- Reusing or porting OpenRCT2 code requires a deliberate GPLv3-or-later compliance plan for the distributed client and any covered work.
- Reusing object-repository files requires distinguishing definitions from media, preserving CC BY attribution and change notices where that license applies, and resolving provenance for any RCT-derived material before shipping it.
- Independently created 3D art avoids dependence on the original image sprites, but OpenGraphics is incomplete and its stated GPLv3 license may constrain the project’s still-undecided licensing choices.
- User-supplied files are not a general substitute for a rights decision. The project still needs to choose local-only processing versus server upload/hosting and verify the EULA for the supported RCT2 distribution.

No license, distribution model, original-save compatibility target, or asset pipeline was selected by this research.
