# OpenRCT2 Simulation Reuse Feasibility

**Static research snapshot: 2026-10-03, commit `11513222890717e81431c83a28aafb7555f2ccd2`.** Source, CMake, browser bootstrap, CI and test definitions were inspected remotely. No OpenRCT2 build, test suite, browser port, benchmark or original-data import was executed. This investigation covers coaster construction, guests and park management together; it does not select an architecture.

## Diagnosis and coupling evidence

OpenRCT2 implements native headless operation and an Emscripten browser build route. These are credible starting points for reuse, but neither the inspected build graph nor browser exports supplies a dedicated simulation library with a versioned 3D-facing API. The strongest existing seam is internal C++: dummy services, object loading, game actions and direct logic ticks, as exercised in upstream test source. The following distinctions matter.

## What the existing Wasm route builds

`scripts/build-emscripten` keeps the GUI, enables SDL2/pthreads, disables network/HTTP/OpenGL/TTF/FLAC/Discord, builds with Ninja and packages `openrct2.*` plus the static page. Its explicit exports are `_main`, `_GetVersion` and optionally `LoadGameCallback`; runtime exports provide filesystem/call helpers. The page creates a canvas, mounts IDBFS, obtains assets and calls `main`; C++ registers its full frame loop with Emscripten. This is a browser application port, not a tick/action/snapshot facade. [build script](https://github.com/OpenRCT2/OpenRCT2/blob/11513222890717e81431c83a28aafb7555f2ccd2/scripts/build-emscripten#L14-L40), [bootstrap](https://github.com/OpenRCT2/OpenRCT2/blob/11513222890717e81431c83a28aafb7555f2ccd2/emscripten/static/index.js#L55-L146), [frame loop](https://github.com/OpenRCT2/OpenRCT2/blob/11513222890717e81431c83a28aafb7555f2ccd2/src/openrct2/Context.cpp#L1204-L1217)

A repository CI job is configured to build and upload that route. This is upstream build-integration evidence, not confirmation of a successful run at this SHA or a supported embedding contract. The script's 2-GiB initial memory, 4-GiB maximum and 120-thread pool are settings to investigate, not measured requirements for a stripped core. [CI job](https://github.com/OpenRCT2/OpenRCT2/blob/11513222890717e81431c83a28aafb7555f2ccd2/.github/workflows/ci.yml#L733-L755), [memory/thread flags](https://github.com/OpenRCT2/OpenRCT2/blob/11513222890717e81431c83a28aafb7555f2ccd2/scripts/build-emscripten#L29-L31)

## Feasibility routes

- **Reference-only rewrite:** independently implement all three gameplay domains and use upstream behavior/tests as comparison material. This avoids extraction coupling but requires rebuilding their interactions and validating fidelity.
- **Selected subsystem adaptation:** construction descriptors, ratings or pathfinding could be bounded candidates, but they depend on ride/map state and metadata. Construction performs map clearance and ownership checks; ratings traverse map elements; pathfinding resolves ride queues. Adapting them is not simply copying standalone formulas. [construction](https://github.com/OpenRCT2/OpenRCT2/blob/11513222890717e81431c83a28aafb7555f2ccd2/src/openrct2/actions/track/TrackPlaceAction.cpp#L184-L290), [ratings traversal](https://github.com/OpenRCT2/OpenRCT2/blob/11513222890717e81431c83a28aafb7555f2ccd2/src/openrct2/ride/RideRatings.cpp#L370-L387), [queue traversal](https://github.com/OpenRCT2/OpenRCT2/blob/11513222890717e81431c83a28aafb7555f2ccd2/src/openrct2/peep/GuestPathfinding.cpp#L1698-L1749)
- **Headless/Wasm core:** retain interacting gameplay and add a deliberate facade. This retains upstream interactions conceptually, while inheriting singleton, object and platform dependencies. `init/query/enqueue/step/snapshot/reset` is a proposed seam, not existing browser API.

## Minimal extraction experiment — proposed, not run

First link a native harness to the full core with GUI and optional services disabled. Retain PNG, zlib, zstd, libzip, ICU and threading where required; scripting is separately configurable. [dependencies](https://github.com/OpenRCT2/OpenRCT2/blob/11513222890717e81431c83a28aafb7555f2ccd2/src/openrct2/CMakeLists.txt#L120-L211), [optional features](https://github.com/OpenRCT2/OpenRCT2/blob/11513222890717e81431c83a28aafb7555f2ccd2/CMakeLists.txt#L106-L120) Use a deliberately small, independently authored park/metadata fixture: one tested coaster, connected queue/exit, guests, staff and treasury. Replay fixed seeds and commands for legal/illegal placement, testing/opening, price changes and path disconnection.

Compare an unchanged native baseline against a headless Emscripten facade using identical fixtures. Check action completion tick, errors/costs, guest/queue transitions, vehicle motion, ratings and financial state after each tick; repeat reset/load to expose global-state leakage. Export copied batches, measure boundary cost, tick time and memory, and inventory remaining presentation calls. Upstream replay tests provide an existing mismatch-checking pattern, not proof of cross-platform equivalence. [replay test](https://github.com/OpenRCT2/OpenRCT2/blob/11513222890717e81431c83a28aafb7555f2ccd2/test/tests/ReplayTests.cpp#L70-L102)

**Open unknowns:** successful build at this pin; sufficient independent metadata; native/Wasm determinism; lifecycle/reset completeness; 3D pose/topology coverage; and acceptable transfer/performance budgets. License/content choices remain in [the separate reuse-conditions report](source-assets.md), and target scale/browser budgets in [the runtime report](browser-runtime.md). No route was selected.
