# Preserve exact saved curve rule banks across runtimes

On 2026-10-14, the designated-host native browser rejected an authentic Node
save as WRONG_RULES even though the shipped source, Worker modules and input
payload matched their complete byte manifests. A separate browser diagnostic
found 26 saved curve-coordinate leaves differed between Node and Chrome by at
most 1.421e-14. Runtime trigonometry had made complete saved numerical Rules
incompatible across the two receiving environments.

Use one literal quarter-curve bank for newly constructed parks. Its values
preserve the observed Node Rules exactly; derive only the existing sampled
stride, radius scale and mirrored direction. Keep the complete observed
pre-fix Chrome bank as a private receiving alternative for saves 15 and 16.
A receiving park recognizes a whole exact serialized bank, retains that bank
as its active numerical authority, and propagates the selected channel pieces
into course compilation. Unobserved, hybrid, custom and modified banks remain
subject to the existing exact receiving check.

Rules-bank selection participates in the save transaction: validate with the
selected bank and fresh routes, restore the previous Rules/routes on failure,
and replace state and invalidate geometry caches only on successful receiving.
The published save/content/protocol versions remain 16/9/9. Existing earlier
receiving conventions and continuous rendering/pose calculations are outside
this compatibility alternative.

Rounding every coordinate, accepting an epsilon, or rewriting a received save
to the current bank would broaden the accepted Rules or silently change saved
numerical authority. Exact known alternatives are intentionally finite. Add
an alternative only with an authentic complete saved witness and independent
receiving, rejection and continuation checks; a new numerical contract may
instead warrant an explicit migration.

Persisted JSON cannot represent signed-zero bits. Regression assertions compare
public profile projections through the same JSON representation as authentic
saved Rules; this does not normalize production coordinates or relax any of
the 26 nonzero compatibility values.

Actual designated-host evidence: the pre-fix baseline reproduced both intended
WRONG_RULES failures; 13 public Engine/Host regression cases and 89 integration
checks passed after the repair. Authentic compressed fixtures and provenance
are under test/fixtures/cross-runtime-rules. Full evidence and prior failed
signed-zero oracle attempts are linked by PROGRESS.md to runtime/
cross-runtime-rules-root-r1, r2 and r3. These CPU results qualify the bounded
repair, not current browser pixels, representative GPU performance, complete
original gameplay fidelity or human acceptance.
